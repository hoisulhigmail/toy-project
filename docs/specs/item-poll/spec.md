# 항목 투표

총무가 활동, 메뉴, 장소 같은 후보 항목을 넣어 투표를 만들면, 대상 팀원이 마음에 드는 항목을 여러 개 고르고 결과를 봅니다. 날짜 투표와 같은 입장, 대상, 마감, 진행률 규칙을 씁니다. 앱 전체의 방향은 [PRODUCT.md](../../../PRODUCT.md), 용어는 [GLOSSARY.md](../../../GLOSSARY.md)의 **항목 투표**와 **후보 항목**을 따릅니다.

## Linked sources

- [team-identity](../../decisions/team-identity.md): 입장 방식, 총무 구분, 데이터 저장소를 정합니다.
- [ui-composition](../../decisions/ui-composition.md): 만들기·투표·결과 화면의 component, 레이아웃, 상태 표현을 정합니다.
- [roster-and-date-poll](../roster-and-date-poll/spec.md): 투표·수정·마감·결과 강조·진행률·미투표자 메일 복사의 기존 동작입니다. 항목 투표는 "후보 날짜" 대신 "후보 항목"을 쓴다는 점만 다르고 나머지 규칙은 같습니다.
- [small-group-poll](../small-group-poll/spec.md): 투표 대상(명단 전체/소그룹)과 대상이 아닌 사람의 화면입니다. 항목 투표에도 그대로 적용됩니다.
- 승인된 프로토타입은 없습니다.

## User-visible outcomes

1. 총무는 제목, 설명, 후보 항목, 마감 일시, 대상을 넣어 항목 투표를 만들고 공유 URL을 얻습니다.
2. 대상 팀원은 공유 URL에서 후보 항목을 여러 개 골라 투표하고, 마감 전까지 수정할 수 있습니다.
3. 투표한 팀원은 항목별 득표 수와 가장 많이 선택된 항목의 강조를 봅니다.
4. 총무 화면은 날짜 투표와 항목 투표를 구분해 보여 주고, 항목 투표의 진행률과 미투표자도 같은 방식으로 보여 줍니다.

## Scope

### 만들기

- 총무 화면에 "새 날짜 투표"와 "새 항목 투표"가 따로 있습니다.
- 항목 투표는 제목, 설명, 후보 항목, 마감 일시, 투표 대상을 넣어 만듭니다. 제목, 설명, 마감 일시, 대상의 규칙은 날짜 투표와 같습니다.
- 후보 항목은 한 줄짜리 글로 넣고, 항목 칸을 추가하거나 뺄 수 있습니다.
- 앞뒤 공백은 지우고, 빈 칸은 무시하며, 같은 글은 한 번만 들어갑니다.
- 남은 후보 항목이 2개보다 적으면 투표가 만들어지지 않고 이유가 보입니다.
- 후보 항목은 총무가 넣은 순서대로 보여 줍니다.

### 투표하기

- 대상 팀원은 공유 URL에서 제목과 설명, 그 아래 후보 항목 목록을 봅니다.
- 마음에 드는 항목을 여러 개 골라 제출하며, 하나 이상 골라야 제출할 수 있습니다.
- 제출 후 결과 화면으로 넘어가고, 마감 전에는 이전 선택이 채워진 상태로 수정할 수 있습니다. 한 사람의 표는 항상 하나로만 집계됩니다.
- 대상이 아닌 사람, 마감 후 동작은 날짜 투표와 같습니다.

### 결과 보기

- 항목별 득표 수와 "N명 투표 · 전체(또는 대상) M명"을 보여 줍니다.
- 득표가 가장 많은 항목을 다른 색으로 강조하고, 동점이면 모두 강조합니다. 표가 없으면 강조하지 않습니다.
- 팀원에게는 누가 무엇을 골랐는지 보이지 않습니다. 이는 후속 "결과 공개 범위 설정"까지의 임시 동작이며 날짜 투표와 같습니다.

### 총무 화면

- 투표 목록의 각 투표에는 "날짜" 또는 "항목" 표시가 붙습니다.
- 항목 투표의 진행률, 미투표자, 미투표자 메일 복사, 공유 URL 복사, 투표하러 가기는 날짜 투표와 같습니다.

## Acceptance criteria

- 총무 화면에 "새 날짜 투표"와 "새 항목 투표"가 각각 있다.
- 후보 항목 3개("볼링", "방탈출", "바비큐")와 미래의 마감 일시로 항목 투표를 만들면, 총무 화면 목록에 "항목" 표시와 "투표 완료 0 / 전체 M"이 보인다.
- 후보 항목을 1개만 넣거나, 같은 글 두 개와 빈 칸만 넣으면 투표가 만들어지지 않고 이유가 보인다.
- " 볼링 ", "볼링", "방탈출"을 넣으면 후보 항목은 "볼링", "방탈출" 두 개로 만들어진다.
- 팀원이 공유 URL에서 후보 항목을 넣은 순서대로 보고, 2개를 골라 제출하면 결과 화면에서 그 2개의 득표가 1씩 늘어 보인다.
- 같은 팀원이 선택을 다른 항목 1개로 바꾸면 이전 항목의 득표가 줄고 투표 인원은 그대로다.
- 득표가 가장 많은 항목만 강조되고, 동점이면 그 항목들이 모두 강조된다.
- 팀원 결과 화면에 다른 사람의 이름이나 개별 선택이 보이지 않는다.
- 소그룹 항목 투표에서 대상이 아닌 사람은 "이 투표의 대상이 아닙니다"만 본다.
- 마감 일시가 지난 항목 투표는 제출할 수 없고, 결과와 마감 안내만 보인다.
- 다른 투표의 후보 항목으로는 제출이 거절된다.
- 기존 날짜 투표는 이전과 똑같이 동작하고, 목록에 "날짜" 표시가 붙는다.

## Settled constraints

- 이번 스펙은 항목 투표 단독입니다. 날짜 투표와 항목 투표를 하나의 묶음으로 만들고 같이 또는 순서대로 여는 기능은 다루지 않습니다. 순서대로 열기는 총무의 최종 날짜 확정이 있어야 성립하므로, 그 기능과 함께 다음 스펙에서 다룹니다.
- 입장, 대상, 마감, 결과 공개 범위(임시), 진행률 규칙은 날짜 투표와 같습니다. 투표 종류마다 규칙이 갈라지지 않게 하기 위해서입니다.

## Assumptions

- 중복 선택만 지원합니다. 단일 선택은 후속 "투표 방식 설정"에서 다룹니다.
- 후보 항목은 2개 이상이어야 합니다. 선택지가 하나뿐이면 투표로서 의미가 없다고 봅니다.
- 후보 항목은 글만 받습니다. 링크, 이미지, 설명 같은 항목별 부가 정보는 없습니다.
- 만든 뒤의 내용 수정과 삭제는 날짜 투표와 같이 범위에 없습니다.

## Off-limits

- 날짜·항목 묶음 구성, 같이 열기와 순서대로 열기, 총무 최종 날짜 확정: 다음 스펙입니다.
- 단일 선택, "모두 좋음" 같은 특수 항목, 불가능한 항목 묻기: 후속 "투표 방식 설정"입니다.
- 결과 공개 범위 설정, 공지 메일 초안, Markdown 내보내기: 후속 스펙입니다.
- 스펙이 요구하지 않은 보안 하드닝과 성능 방어: 이 프로젝트의 검증 예산 밖입니다.

## Deferred points

- 결과 공개 범위: 후속 "결과 공개 범위 설정"이 정합니다. 그전까지는 득표 수만 보여 줍니다(임시).

## Remaining risks

- 이름+사번 식별의 사칭 위험은 [team-identity](../../decisions/team-identity.md)에서 수용한 범위 그대로입니다.
- 항목 글의 길이에 제한을 두지 않아서, 아주 긴 글이 화면 배치를 흐트러뜨릴 수 있습니다.
