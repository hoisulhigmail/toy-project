# 공지 메일 초안과 결과 기록

투표가 마감되면 총무가 결과로 만든 **공지 메일 초안**을 복사해 팀에 알리고, **결과 기록**을 Markdown 파일로 받아 history로 남깁니다. PRODUCT.md 핵심 흐름의 마지막 단계(공지와 기록으로 투표를 마무리)를 채우는 작업입니다. 앱 전체의 방향은 [PRODUCT.md](../../../PRODUCT.md), 용어는 [GLOSSARY.md](../../../GLOSSARY.md)의 **공지 메일 초안**과 **결과 기록**을 따릅니다.

## Linked sources

- [ui-composition](../../decisions/ui-composition.md): 총무 화면에 더해지는 버튼과 안내의 component, 상태 표현을 정합니다.
- [roster-and-date-poll](../roster-and-date-poll/spec.md), [small-group-poll](../small-group-poll/spec.md), [item-poll](../item-poll/spec.md): 득표 수, 최다 선택지 강조(동점 포함), 투표 인원, 전체/대상 표기의 현재 규칙입니다. 초안과 기록은 이 규칙으로 계산된 결과를 그대로 옮깁니다.
- 승인된 프로토타입은 없습니다. 공지 메일 초안의 구성은 아래 Scope에 확정된 예시로 둡니다.

## User-visible outcomes

1. 마감된 투표의 총무 화면 카드에서 "공지 메일 복사"를 누르면, 결과로 만든 메일 제목과 본문이 클립보드에 들어갑니다.
2. 같은 카드에서 "Markdown 받기"를 누르면, 결과 기록 파일이 내려받아집니다.
3. 두 결과물 모두 사람 이름 없이 집계 결과만 담습니다.

## Scope

### 쓸 수 있는 시점

- 두 버튼은 마감된 투표의 카드에만 나타납니다. 진행 중인 투표에는 보이지 않습니다.
- 총무 화면에서만 씁니다. 팀원 화면에는 나타나지 않습니다.

### 공지 메일 초안

날짜 투표의 예는 아래와 같고, 사용자와 확정한 구성입니다.

```
제목: [결과 안내] 가을 야유회 날짜

안녕하세요, 가을 야유회 날짜 투표 결과를 안내드립니다.

■ 가장 많이 가능한 날: 11월 7일 (토) — 18표
■ 투표 인원: 32명 / 전체 38명
■ 마감: 2026. 10. 30. (금) 18:00

[날짜별 결과]
- 11월 6일 (금): 12표
- 11월 7일 (토): 18표
- 11월 13일 (금): 9표

감사합니다.
```

- 첫 줄은 `제목: [결과 안내] {투표 제목}`이고, 빈 줄 다음부터 본문입니다. 버튼 하나로 제목과 본문을 함께 복사합니다.
- 항목 투표는 "가장 많이 선택된 항목: {항목} — N표"와 "[항목별 결과]"를 씁니다.
- 동점이면 최다 선택지를 쉼표로 이어 "{선택지}, {선택지} — 각 N표"로 적습니다.
- 표가 하나도 없으면 최다 줄은 "{가장 많이 가능한 날 / 가장 많이 선택된 항목}: 없음 (투표 없음)"으로 적습니다.
- 소그룹 투표는 투표 인원 줄에 "전체" 대신 "대상"을 씁니다.
- 선택지별 결과는 결과 화면과 같은 순서로 적습니다. 날짜는 날짜순, 항목은 총무가 넣은 순서입니다.
- 투표 설명은 넣지 않습니다.
- "확정"이라는 말은 쓰지 않습니다. 총무의 최종 확정 기능은 아직 없기 때문입니다.
- 복사하면 기존 복사 버튼처럼 잠깐 복사 완료 안내가 보입니다.

### 결과 기록 (Markdown)

- 투표 제목, 설명, 투표 종류(날짜/항목), 대상(전체/소그룹), 마감 일시, 투표 인원("N명 / 전체(또는 대상) M명"), 최다 선택지, 선택지별 득표 표를 담습니다.
- 최다 선택지와 동점, 표 없음의 표기는 공지 메일 초안과 같습니다.
- 사람 이름은 하나도 담지 않습니다. 투표한 사람, 투표하지 않은 사람, 개인별 선택 모두 해당합니다.
- 파일 이름은 `{마감일 YYYY-MM-DD}-{투표 제목}.md`입니다. 파일 이름에 쓸 수 없는 문자는 `-`로 바꿉니다.
- 집계 기준 시점은 파일을 받는 시점의 명단입니다. 명단 변경이 집계에 반영되는 규칙은 기존과 같습니다.

## Acceptance criteria

- 진행 중인 투표의 카드에는 "공지 메일 복사"와 "Markdown 받기"가 없고, 마감된 투표의 카드에는 둘 다 있다.
- 마감된 날짜 투표에서 "공지 메일 복사"를 누르면, 위 예시와 같은 구성(제목 줄, 인사, 최다 날짜와 표 수, 투표 인원과 전체 인원, 마감 일시, 날짜별 결과, 맺음말)의 글이 클립보드에 들어가고 복사 완료 안내가 보인다.
- 마감된 항목 투표의 초안에는 "가장 많이 선택된 항목"과 "[항목별 결과]"가 쓰이고, 항목이 넣은 순서대로 나온다.
- 최다 선택지가 동점이면 초안에 동점인 선택지가 모두 "각 N표"로 적힌다.
- 표가 없는 마감 투표의 초안에는 최다 줄에 "없음 (투표 없음)"이 적힌다.
- 소그룹 투표의 초안과 기록에는 "대상 M명"이 쓰이고, M은 대상 수다.
- "Markdown 받기"를 누르면 `{마감일}-{제목}.md` 파일이 내려받아지고, 내용에 제목, 설명, 종류, 대상, 마감, 투표 인원, 최다 선택지, 선택지별 득표 표가 있다.
- 초안과 기록 어디에도 명단에 있는 사람의 이름이 나오지 않는다.
- 초안과 기록의 숫자는 같은 시점의 결과 화면 숫자와 같다.

## Settled constraints

- 공지 메일 초안 구성은 Scope의 예시로 확정했습니다. 총무가 그대로 붙여 넣어 보낼 수 있는 완성된 글이어야 하기 때문입니다.
- 결과 기록에는 사람 이름을 전혀 넣지 않습니다. 기록은 Confluence 같은 곳에 오래 남는데, 개인별 정보의 공개 범위는 아직 "결과 공개 범위 설정"에서 정하지 않았기 때문입니다. 투표자 명단도 같은 이유로 넣지 않습니다.
- 초안은 "확정"이 아니라 "가장 많이 가능한 날 / 가장 많이 선택된 항목"으로 적습니다. 최종 확정 기능은 다음 스펙입니다.

## Assumptions

- 두 기능은 마감된 투표에서만 씁니다. 중간 현황 공지는 필요가 확인되면 후속으로 다룹니다.
- 공지 메일의 받는 사람은 초안에 넣지 않습니다. 총무가 메일 프로그램에서 직접 고릅니다.
- 결과 기록은 사람이 읽기 좋은 Markdown 형식이면 충분하고, 정해진 Confluence 양식은 없습니다.

## Off-limits

- Confluence 직접 게시: PRODUCT.md에서 접근 확인 후 확장하기로 한 범위입니다.
- 메일 발송: PRODUCT.md 범위 밖입니다.
- 총무의 최종 날짜 확정과 확정 문구: 다음 스펙입니다.
- 개인별 선택이나 투표자 명단을 담는 기록: "결과 공개 범위 설정"이 정해진 뒤 다시 다룹니다.
- 스펙이 요구하지 않은 보안 하드닝과 성능 방어: 이 프로젝트의 검증 예산 밖입니다.

## Deferred points

None identified.

## Remaining risks

- 사내 메일 프로그램이 붙여 넣은 글의 줄바꿈이나 "■" 기호를 다르게 보여 줄 수 있습니다. 실제 Outlook에 붙여 넣어 보는 확인은 사용자 몫입니다.
- 투표 제목에 특수 문자가 많으면 파일 이름이 `-`로 많이 바뀌어 알아보기 어려울 수 있습니다.
