# 모두가능 선택지와 투표 삭제

날짜 투표에 "모두가능" 선택지를 넣을 수 있게 하고, 총무가 만든 투표를 지울 수 있게 합니다. 앱 전체의 방향은 [PRODUCT.md](../../../PRODUCT.md), 용어는 [GLOSSARY.md](../../../GLOSSARY.md)의 **모두가능**을 따릅니다.

## Linked sources

- [team-identity](../../decisions/team-identity.md): 총무 구분 방식을 정합니다. 삭제 권한은 이 구분을 따릅니다.
- [ui-composition](../../decisions/ui-composition.md): 선택지, 삭제 버튼, 확인 창의 component와 상태 표현을 정합니다.
- [roster-and-date-poll](../roster-and-date-poll/spec.md): 날짜 투표의 투표·수정·집계·강조 규칙입니다. 모두가능은 이 규칙 위에서 동작합니다.
- [poll-announcement](../poll-announcement/spec.md): 공지 메일 초안과 결과 기록은 날짜별 득표를 그대로 옮기므로, 모두가능의 표도 날짜별 득표에 들어간 상태로 나옵니다.
- 승인된 프로토타입은 없습니다.

## User-visible outcomes

1. 총무는 날짜 투표를 만들 때 "모두가능" 선택지를 넣을지 고릅니다.
2. 모두가능이 있는 날짜 투표에서 팀원이 모두가능을 고르면 모든 후보 날짜에 1표씩 더해집니다.
3. 총무는 총무 화면에서 투표를 지울 수 있고, 지운 투표의 공유 URL은 투표가 없다고 안내합니다.

## Scope

### 모두가능 선택지

- 날짜 투표 만들기 화면에 "모두가능 선택지 넣기"가 있고, 처음에는 켜져 있습니다. 항목 투표 화면에는 없습니다.
- 켜고 만든 날짜 투표의 투표 화면에는 후보 날짜 목록 맨 위에 "모두가능"이 보입니다. 끄고 만든 투표에는 보이지 않습니다.
- 모두가능을 고르면 모든 후보 날짜가 함께 체크되고, 해제하면 모두 해제됩니다.
- 모두가능이 체크된 상태에서 날짜를 하나라도 해제하면 모두가능도 해제됩니다. 모든 날짜를 하나씩 체크해도 모두가능이 체크된 상태로 보입니다.
- 모두가능으로 제출한 표는 모든 후보 날짜를 고른 표와 똑같이 집계됩니다. 결과 화면, 총무 화면, 공지 메일 초안, 결과 기록에는 "모두가능" 줄을 따로 두지 않습니다.

### 투표 삭제

- 총무 화면의 각 투표 카드에 "삭제" 버튼이 있습니다. 진행 중이든 마감이든 지울 수 있습니다.
- 누르면 확인 창이 뜨고 "이 투표와 모든 표가 지워지며 되돌릴 수 없습니다"라고 알립니다. 확인하면 지워지고, 취소하면 아무 일도 없습니다.
- 지우면 그 투표의 후보 날짜·항목, 대상, 표가 모두 함께 지워지고 목록에서 사라집니다.
- 지운 투표의 공유 URL을 열면 "투표를 찾을 수 없습니다" 안내가 보입니다.
- 총무가 아닌 사람의 삭제 요청은 거절됩니다.

## Acceptance criteria

- 날짜 투표 만들기 화면에 "모두가능 선택지 넣기"가 켜진 상태로 있고, 항목 투표 만들기 화면에는 없다.
- 모두가능을 켜고 만든 날짜 투표의 투표 화면에는 "모두가능"이 맨 위에 있고, 끄고 만든 투표에는 없다.
- 팀원이 모두가능을 체크하면 모든 날짜가 체크되고, 제출하면 모든 날짜의 득표가 1씩 늘어 보인다.
- 모두가능 상태에서 날짜 하나를 해제하면 모두가능이 해제된다. 수정 화면에서 모든 날짜를 고른 표는 모두가능이 체크된 상태로 열린다.
- 공지 메일 초안과 결과 기록의 날짜별 득표는 모두가능 표가 반영된 결과 화면 숫자와 같다.
- 총무 화면의 각 투표 카드에 "삭제"가 있고, 누르면 확인 창이 뜬다. 취소하면 투표가 남아 있다.
- 확인하면 투표가 목록에서 사라지고, 그 공유 URL은 "투표를 찾을 수 없습니다"를 보여 준다.
- 총무가 아닌 사람이 삭제를 직접 요청하면 거절되고 투표는 남는다.

## Settled constraints

- 모두가능은 날짜 투표에만 둡니다. 항목 투표는 선호를 가려내는 것이 목적인데, "모두 좋음"이 많아지면 그 차이가 흐려지기 때문입니다.
- 모두가능 표는 모든 날짜를 고른 표와 같게 집계합니다. PRODUCT.md의 "모두가능을 고르면 모든 날짜에 +1" 규칙을 그대로 따릅니다.

## Assumptions

- 모두가능의 기본값은 켜짐입니다. 대부분의 날짜 조사에서 편하다고 봅니다.
- 이미 만든 날짜 투표는 모두가능이 꺼진 상태로 둡니다.
- 삭제에는 되돌리기가 없고, 확인 창 한 번으로 충분하다고 봅니다.

## Off-limits

- 불가능한 날 묻기, 단일 선택: 후속 "투표 방식 설정"입니다.
- 항목 투표의 "모두 좋음": 위 Settled constraints의 이유로 넣지 않습니다.
- 투표 내용 수정, 삭제 되돌리기: 필요가 확인되면 후속으로 다룹니다.
- 스펙이 요구하지 않은 보안 하드닝과 성능 방어: 이 프로젝트의 검증 예산 밖입니다.

## Deferred points

None identified.

## Remaining risks

- 삭제는 되돌릴 수 없어서, 확인 창에서 실수로 확인하면 표가 모두 사라집니다.
- 배포 사이트와 개발 환경이 같은 DB를 쓰므로, 개발 중에 지운 투표는 배포 사이트에서도 사라집니다.
