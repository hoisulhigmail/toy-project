# 팀원 식별과 데이터 저장

## Decisions

- 팀원은 이름과 사번을 입력해 입장하고, 두 값이 모두 인원 명단의 한 사람과 일치할 때만 들어올 수 있습니다.
- 총무는 인원 명단의 총무 표시로 구분합니다. 총무도 같은 방식으로 입장하며, 별도 비밀번호를 두지 않습니다.
- 최초 총무 한 명은 서비스를 준비할 때 미리 명단에 넣어 둡니다.
- 데이터는 Supabase Cloud에 저장합니다. Supabase Auth는 사용하지 않고, 식별은 앱이 인원 명단으로 직접 처리합니다.

## Boundaries

- 이 방식은 사칭을 막지 못합니다. 이름과 사번을 아는 사람은 그 사람으로 입장할 수 있고, 총무의 사번을 알면 총무 화면에도 들어갈 수 있습니다.
- Supabase Auth의 사용자, profiles, `auth.uid()` 기반 RLS 패턴은 이 식별 방식에 맞지 않으므로 그대로 가져오지 않습니다.

## Why

사내 로그인(LG AD) 연동은 IT 승인 여부를 알 수 없어 지금 쓸 수 없고, 이메일·구글 로그인은 팀원 50명에게 계정 생성을 요구해 공유 URL로 바로 투표하는 경험을 해칩니다. 사칭 위험은 사내 취합 용도에서 수용하기로 했습니다.

## Reconsider when

- 사내 로그인(LG AD) 연동이 승인될 때
- 사칭이나 대리 투표가 실제 문제로 보고될 때

## Still-rejected alternatives

- Supabase Auth 이메일·비밀번호 로그인 — 팀원마다 가입이 필요해 투표 진입이 무거워집니다. 실제 인증이 필요해지면 다시 검토합니다.
- 총무 전용 비밀번호 — 공유 비밀번호를 따로 관리해야 하고, 명단 기반 식별과 규칙이 둘로 나뉩니다.
